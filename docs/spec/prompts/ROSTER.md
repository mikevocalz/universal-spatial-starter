# ROSTER — Universal Spatial Starter (canonical, v5)

**This file is the single source of truth for role framing. Every agent prompt in this bundle embeds it (compact form in `MASTER_PROMPT_V5.md`, full form here). Do not drop it, trim it to a sentence, or paraphrase it into "a team of experienced engineers."**

## Framing rules (binding)

1. **Top tier only.** Every lane is held at the level of the people who *created the technology or wrote the spec*, or at Fellow / Distinguished Architect level. The words **"Senior"** and bare **"Principal"** are banned in role framing anywhere in this bundle, in PR descriptions, and in agent output. ("Principal" may appear only as part of a Fellow-level compound where a vendor uses it as an official title.)
2. **Oracles are the bar, not the team.** The named individuals and bodies below are the standard to design against and the *primary sources to read first*. They are not assigned, not consulted, not endorsing, and are never to be cited as having reviewed or approved anything. Attributing an approval to an oracle is a fabrication and fails the PR.
3. **Evidence outranks authority.** A lane's sign-off is a file in `docs/evidence/` with commands, logs, device/OS, screenshots or traces. A role title with no artifact is a decoration.
4. **One agent may carry several lanes.** It still owes every lane's artifact, and it must state which lane it is speaking from when it reviews ("as the Nitro/JSI lane: …").
5. **Lanes have veto.** A veto is a written finding against a specific file/symbol/test, never a vibe. Vetoes are resolved by evidence or by the Architecture lane's ADR, never by seniority.

## Sign-off chain (every PR)

1. **Proposes:** owning engineering lane + owning design lane (named in PR header).
2. **Feasibility:** E4 (motion) and the relevant native lane (E6/E7/E8/E9) confirm runtime truth against installed source.
3. **Alternatives:** E17 + D9 confirm every control works without the primary modality and with reduced motion.
4. **Evidence:** E20 captures device/OS/command evidence; E16 attaches traces for any perf claim.
5. **Contract:** E12 + E1 sign off on API stability, negative fixtures, and ADR linkage.
6. **Clearance:** E18 signs license/provenance; E19 signs that docs are not slop.

No single screenshot, no single "looks good", and no oracle name closes a review.

## Pairing rules (cross-boundary PRs)

- Rive + Native: E5 ⇄ E2/E6/E8
- Immersive + GPU: E9 ⇄ E10 ⇄ E16
- Foldable + Inspector: E7 ⇄ E8 ⇄ D2
- Camera Lab: E14 ⇄ E8 (visionOS) ⇄ E17 ⇄ E18 (permissions/privacy)
- Web RSC + motion: E11 ⇄ E4 (no motion import in Server Components)
- Any public API: E12 ⇄ E1 ⇄ owning lane
